A plain-language guide to the simulator

What Am I Looking At?

No networking background needed. This page explains the story the simulator is telling, what each panel on it means, and five things to try — in order.

The one-sentence version

Four computers are plugged into one box. One of them lies about who it is so that it can read other people’s messages — and a small program is watching for exactly that lie.

Think of an office building with four rooms and one mailroom. Post doesn’t go to rooms, it goes to people — so the mailroom has to keep track of who is in which room.

The way it keeps track is embarrassingly trusting: anybody can walk in and say “I’m in room 3 now.” Nobody asks for ID. The mailroom crosses out the old note and writes the new one.

So the person in room 1 walks in and says “actually, I’m room 3.” From then on, room 3’s post is handed to them. They read it, then quietly pass it along, so nobody notices anything is wrong.

This project adds a doorman who has been there for years. He can’t check anyone’s ID either — but he remembers. He knows the person now claiming room 3 is the same person who has walked in through door 1 as room 1 every single day. That’s enough to catch them.

That is genuinely the whole idea. The rest is vocabulary.

The five things on screen

The simulator is one page with five areas. Here is what each one is for.

  1. 1

    The buttons, along the top

    Nothing happens until you press something. The red button launches the attack; the two little switches turn the defence on and off; reset puts everything back.

  2. 2

    The network picture

    Four computers along the bottom (h1, h2, h3, h4), the switch they all plug into in the middle, and the watching program at the top. Little coloured boxes travel along the lines — those are messages. Blue ones are address questions and answers, red ones are lies.

  3. 3

    The checklist

    Every time the program is asked about a message, it works down the same seven steps. They light up one at a time so you can see which decision it is making. Step 6 turning red means it caught something.

  4. 4

    The log

    The black panel where the program narrates what it is doing. These are the real messages the actual program prints — not a friendly summary. The red lines are the alarm going off.

  5. 5

    The tables along the bottom

    Three kinds of memory. The switch’s standing orders, the program’s record of who is who, and — the important one — what each computer believes about the others. When the attack succeeds, you will see a wrong belief appear in red.

Five things to try, in order

Each one takes a few seconds. If the animation moves too fast, there is a speed control at the top right — set it to 0.5×.

Try 1Watch the attack get caught

pressh1 forges ARP

h1 sends one message claiming to be h3. That is the entire attack — a single sentence, told once.

watch for

A red box leaves h1. The checklist runs down to step 5, then step 6 turns red. A yellow box drops from the program into the switch — that is a new standing order. The line to h1 goes red and dashed with an ✕ through it. h1 is now cut off.

Try 2Turn the blocking off and see what the attack really does

pressresetturn MITIGATION offh1 forges ARP

Now the program still notices — the alarm still goes off in the log — but it doesn’t do anything about it. The lie gets delivered.

watch for

The bottom-right table, what each computer believes. h4’s entry for h3 turns red and now names h1. h4 has been fooled. It thinks h1 is h3.

Try 3See the eavesdropping actually happen

pressh4 → h3 ping

h4 tries to send a normal message to h3. It has been fooled, so it sends it to the wrong place.

watch for

The message goes to h1, not h3. Then h1 passes it on to h3 anyway. That second hop is the whole point of the attack: h1 has read the message, and because it forwarded it, neither h3 nor h4 notices anything is wrong. This is what people mean by a man in the middle.

Try 4Turn the whole defence off

pressresetturn DETECTION offh1 forges ARP

This is what the network looked like before anyone wrote this project.

watch for

The log says nothing. No alarm, no red line, no record. The attack succeeds in total silence — which is exactly why it is dangerous, and why detecting it is worth the effort.

Try 5Find the flaw in the defence

pressreseth1 forges ARPskip 5 min

Block the attacker properly, then let five minutes of quiet pass.

watch for

The red standing order disappears on its own and h1’s line goes back to normal. The block was never permanent. An attacker who simply waits gets let back in, and nobody is told. This is a real weakness in the project, not a bug in the simulator.

One more, if you’re curious

Press reset, then pingAll — learn bindings. You will watch the memory fill up from nothing as the computers introduce themselves to each other. This is the calm before any attack, and it is where the program learns the facts it later uses to catch the liar.

Words you’ll see

Everything on the screen in one of these terms. None of them are as complicated as they look.

MAC address 00:00:00:00:00:01
The permanent serial number stamped on a network card at the factory. Think of it as a passport number — it identifies the machine itself and doesn’t normally change.
IP address 192.168.1.1
The address the machine is using right now, on this particular network. More like a room number than a passport — it can be reassigned.
ARP
The question “who currently has 192.168.1.4?” shouted to everyone, and the answer that comes back. There is no ID check on the answer. This missing check is the entire vulnerability.
Port
The physical socket on the switch that a cable plugs into. h1 is on port 1, h2 on port 2, and so on. A port tells you where something is plugged in, which is a fact an attacker can’t easily fake.
Switch
The box in the middle that all four computers plug into. Its only job is moving messages to the right socket.
Controller
The program at the top of the picture that tells the switch what to do. This project is the controller — about 180 lines of Python.
Flow rule the standing orders
An instruction stored in the switch: “when you see this kind of message, do this.” The switch follows them without asking anyone, which is what makes it fast.
Priority
When two standing orders both apply, the higher number wins. The block on the attacker is priority 101, which is deliberately higher than everything else — that is why it works.
Binding
One machine’s three facts held together: its serial number, its current address, and the socket it’s plugged into. The whole defence is checking that these three keep agreeing with each other.
